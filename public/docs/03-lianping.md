# 直播连屏业务架构体系建设

## 项目背景

连屏 PK 营收占快手直播营收大盘的一半，覆盖亿级用户，业务形态极其丰富：

- 1v1 PK
- 多人连麦
- 九宫格
- 跨房间 PK

每年迭代 20+ 功能，对架构的扩展性和稳定性提出极高要求。

## 挑战

1. **业务复杂度高**：上下游链路长、跨层通信多、音视频状态复杂（3 个角色、6 个团队、2 路采集/6 路输出）
2. **迭代速度快**：业务形态丰富，流程和 UI 多变，扩展性和复用性要求高
3. **稳定性要求高**：流水高、大 V 多，线上稳定性和排障速度要求高

## 技术方案

### 1. 五层插件化架构

从下到上分为：

```
配置层 → 业务层 → 组件层 → 框架层 → 基础层
```

场景可插拔，每个业务可以按需组合能力。

### 2. 功能复用框架

插件跨业务可插拔、同业务支持不同模式。

### 3. 统一 UI 管理框架

- **窗格层**：管理视频窗格布局
- **玩法层**：管理 PK 玩法状态
- **临时状态层**：管理弹窗、特效等临时 UI

### 4. 稳定性建设

- **Trace 排障**：全链路追踪，秒级定位问题
- **多端对账**：客户端与服务端数据一致性校验
- **watchDog**：自动检测异常并恢复

## 核心认知

> 连屏架构的核心挑战不是技术难度，而是**在快速变化的业务需求中保持架构的稳定性与扩展性**。五层插件化架构的本质是让"变化的部分灵活，不变的部分稳定"。
